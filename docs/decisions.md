# 実装時の判断

- 受付・倉庫・機械室・出口の4区画。アイテムは工具、電池、カード各1個。A が電池を一度だけ消費し、B は工具を保持。A/B は任意順。電池を別室へ持ち運べる。
- 操作はカメラから 2.3m の物理 raycast。プレイヤー自身だけを除外し、壁、ガラス、他の物体は遮蔽物とする。照準と対象の取り違えも同じ raycast で決める。
- 物理移動・衝突は CharacterBody3D。段差22cm以内の前方クリアランスを確認して階段を上る。低天井はしゃがみで通り、立ち上がり時に天井を検査する。落下時は受付へ復帰し、アイテムと進行を保持。
- 扉は4秒間開き、プレイヤーが閉鎖面の1m以内にいる間は閉鎖を延期。エレベーターは毎秒1mで上下し、搭乗者を同量移動。移動中の再操作は行き先を反転できる。
- 中断はプレイヤー・扉タイマー・リフト・ゲーム経過時間を止める。Gua と UI の処理は継続する。保存/復帰後に滞留した移動パルスを再実行しない。
- 保存対象は位置、視点、所持品、取得履歴、電源、扉と残り時間、リフト位置と行き先、しゃがみ・ジャム、言語、画面サイズ、実行番号、経過時間、シナリオ・シード・バグ設定。チェックポイントは一時ファイルから rename して置換する。
- 同一フレームは移動とリフト搭乗者移送の後で扉の占有を判定。UI操作は Gua 標準受付・完了イベントを使用する。ポーズ中に移動操作を受けても進行しない。
- headless Godot が返す 64×64 は実画面サイズではないため、設定した論理画面サイズを保存。描画ありでは実ウィンドウサイズを保存。
- リセットは通常プレイ開始と同じ初期化を行うが、選択したバグと設定、既存チェックポイントを保持。乱数は未使用。テスト専用開始位置や即時クリア操作は設けない。
- 素材は生成したプリミティブと文字のみ。音声・素材の外部ライセンス依存なし。Gua と godot-cpp のライセンスは `addons/gua` に保持。
